# 存储与索引

存储层把分块结果按 chunk 角色路由写入向量库与父块库。向量库存子块（参与语义召回），父块库存父块完整原文（供父子回查）。

## 1. 两个数据源

| 数据源 | 存什么 | 是否必填 | 支撑能力 |
|--------|--------|---------|---------|
| VectorStore | 子块（向量化） | 必填 | 向量检索 |
| DocumentStore | 父块原文 | 按需 | 父子回查 |

未配 DocumentStore 时，父块不落地（框架打印 warn 提示），父子回查不可用。

## 2. 写入门面 RagDocumentStore

```java
RagDocumentStore store = RagDocumentStore.builder()
        .vectorStore(vectorStore)          // 必填：Spring AI VectorStore
        .documentStore(documentStore)      // 可选：父子回查需要
        .embeddingBatchSize(10)            // 可选：单次 embedding 调用文档数，默认 10
        .build();

store.index(documentId, chunks);                                // 建索引
store.index(documentId, chunks, Map.of("docType", "aicube"));   // 建索引 + 注入自定义 metadata
store.deleteByDocumentId(documentId);                           // 删整个文档
```

`index` 参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| documentId | String | 文档唯一标识，建议用内容 hash 实现幂等 |
| documents | List\<Document\> | 分块结果 |
| extraMetadata | Map\<String,Object\> | 可选，统一注入到所有块的 metadata（如 docType） |

`index` 是「先删后插」：同一 documentId 重复执行会替换旧数据，不累积。

## 3. 向量库：PgVectorStore

调用方直接用 Spring AI 原生 `PgVectorStore.builder()` 构建，框架不封装：

```java
PgVectorStore vectorStore = PgVectorStore.builder(jdbcTemplate, embeddingModel)
        .dimensions(1024)                                  // 向量维度，需匹配 embedding 模型
        .distanceType(PgVectorStore.PgDistanceType.COSINE_DISTANCE)  // 距离度量
        .indexType(PgVectorStore.PgIndexType.HNSW)         // 索引类型
        .vectorTableName("表名")                            // 表名
        .initializeSchema(true)                            // 自动建表
        .build();
vectorStore.afterPropertiesSet();
```

PG 的 metadata 整包 JSON 存一列，任意字段都能 filter，无需预注册。

## 4. 向量库：RedisVectorStore

框架提供 `RedisVectorStores` 工厂：

```java
// 默认：契约字段全量注册，索引名 agentx-rag-vector，前缀 rag:
RedisVectorStore vectorStore = RedisVectorStores.create(jedis, embeddingModel);

// 自定义索引名与前缀
RedisVectorStores.create(jedis, embeddingModel, "索引名", "key前缀");

// 完整：契约字段 + 追加自定义字段
RedisVectorStores.create(jedis, embeddingModel, "索引名", "key前缀",
        RedisVectorStore.MetadataField.tag("docType"));
```

`create` 参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| jedis | JedisPooled | Redis 连接 |
| embeddingModel | EmbeddingModel | embedding 模型 |
| indexName | String | RediSearch 索引名，默认 agentx-rag-vector |
| prefix | String | key 前缀，默认 rag: |
| extraFields | MetadataField... | 可选，追加注册的自定义字段 |

`MetadataField` 三种类型（按字段值类型选择）：

- `MetadataField.tag("字段名")` — 精确匹配（字符串、布尔、多值）
- `MetadataField.numeric("字段名")` — 数值过滤
- `MetadataField.text("字段名")` — 全文检索

## 5. 父块库：DocumentStore

```java
// JDBC（PG，自动建表）
new JdbcDocumentStore(dataSource);
new JdbcDocumentStore(dataSource, "自定义表名");   // 第二个参数：表名，默认 agentx_rag_document

// Redis
new RedisDocumentStore(stringRedisTemplate);
```

## 6. PG 与 Redis 的差异（重要）

两者 metadata 能力不同，源于 Spring AI 的原生设计，框架如实暴露、不重复造底层：

| 维度 | PG | Redis |
|------|----|----|
| metadata 存储 | 整包 JSON 存一列 | 平铺到 JSON 顶层 |
| 检索结果回读 | 整包返回 | 只返回「注册过的字段」 |
| 字段过滤 | 任意字段直接 filter | 需先注册字段 |

框架对 Redis 的处理：

- **契约字段**（chunkId / parentChunkId / fileName / contentType 等 20 个）已默认全量注册，检索结果全量回读
- **自定义字段**（如 docType）要 filter 或回读，需通过 `extraFields` 注册

两个注意点：

1. Redis 下含空格的 metadata 值（如文件名）不能做 TAG 精确过滤，建议用 documentId 过滤
2. Redis 索引字段清单变更后，需手动 `FT.DROPINDEX` 重建索引（Spring AI 不自动重建）

## 7. 框架接管 vs 调用方传递

| 职责 | 谁负责 |
|------|--------|
| 路由（子块进向量库、父块进父块库）、先删后插、契约字段注册 | 框架 |
| 向量库/父块库选型与连接 | 调用方 |
| 自定义 metadata 注入 | 调用方（index 时传 extraMetadata） |
| Redis 自定义字段注册 | 调用方（extraFields） |
