# 编排与接入

编排层把查询增强、检索、重排串成一条管道。框架提供两种接入方式：串行 RAG（线性管道）与 Agentic RAG（RAG 作为工具交给智能体）。

## 1. RagPipeline 编排

```java
RagPipeline pipeline = DefaultRagPipeline.builder()
        .queryTransformer(QueryTransformers.compression(chatModel))   // 可选，可多个
        .queryTransformer(QueryTransformers.hyde(chatModel))
        .queryExpander(QueryExpanders.multiQuery(chatModel))           // 可选
        .documentRetriever(EnhancedRetriever.builder()
                .vectorStore(vectorStore)
                .documentStore(parentStore)
                .enableParentChild(true)
                .build())                                              // 必填
        .reranker(new HttpReranker(baseUrl, apiKey, model, topK))      // 可选
        .build();

List<Document> docs = pipeline.retrieve("问题", chatHistory);
```

`builder` 参数：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| queryTransformer | QueryTransformer | 否 | 1→1 转换器，可追加多个，按顺序串行 |
| queryExpander | QueryExpander | 否 | 1→N 扩展器，最多一个 |
| documentRetriever | DocumentRetriever | 是 | 检索器 |
| reranker | Reranker | 否 | 精排 |

`retrieve` 参数：

| 参数 | 类型 | 说明 |
|------|------|------|
| question | String | 用户问题 |
| chatHistory | List\<Message\> | 对话历史，多轮对话用于消解指代，可传空 |

骨架固定：**transformer 链（按传入顺序串行）→ expander（1→N）→ 逐 query 检索去重 → reranker 精排**。

- transformer 不传 = 纯检索，框架不猜、不额外花 LLM 调用
- 顺序由调用方决定（transformer 链按追加顺序执行）
- 调用方想非标编排，可 `implements RagPipeline` 自己实现，或单独拿各层组件手动串

## 2. 串行 RAG（线性管道）

```java
List<Document> docs = pipeline.retrieve(question, chatHistory);
// 拿 docs 拼上下文，交给 ChatClient 总结
```

多轮对话时，`chatHistory` 传对话历史（用于 compression 消解指代）。core 模块提供 `ChatHistorySelector` 提取最近 QA：

```java
List<Message> history = chatHistorySelector.recentQa(conversationId, 6);
// 参数：conversationId 会话 ID、limit 提取最近 QA 条数
```

## 3. Agentic RAG（RAG 作为工具）

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .thinkingMode(ThinkingMode.REASONING_CONTENT)
        .tools(RagRetrievalTool.of(pipeline))
        .instructions("...")     // 提示词里约定 Markdown 输出、图片渲染、信息不足说明等
        .build();

agent.streamForResult(question, params)
        .doOnNext(TestConfig::printEvent)
        .blockLast();
```

`RagRetrievalTool.of(pipeline)` 把 pipeline 封装成 Spring AI ToolCallback，注册到 ReactAgent 后，由 LLM 自主决定何时检索、用什么关键词、是否换个词重试。

## 4. 两种方式怎么选

| 场景 | 方式 |
|------|------|
| 流程固定、追求可控、检索一次 | 串行 RAG |
| 需要判断「要不要检索/检索几次」、多工具协作 | Agentic RAG |

## 5. 完整示例（解析 → 分块 → 存储 → 检索 → 问答）

```java
// 1. 解析
RawDocument rawDocument = new LocalDocumentReader(path).read();
List<Document> docs = MineruDocumentParser.builder()
        .authToken(token).enableImageUnderstanding(true)
        .imageChatModel(vlm).assetStore(minioStore)
        .build().parseToDocuments(rawDocument);

// 2. 分块
List<Document> chunks = HeadingSplitter.builder()
        .maxHeadingLevel(2).chunkSize(600).overlap(80)
        .enableParentChild(true).build().split(docs);

// 3. 存储
RagDocumentStore store = RagDocumentStore.builder()
        .vectorStore(vectorStore).documentStore(parentStore).build();
store.index(DocumentIdGenerator.getDocId(rawDocument.content()), chunks,
        Map.of("docType", "aicube"));

// 4. 检索（串行 RAG 或 Agentic RAG 二选一）
List<Document> result = pipeline.retrieve("问题", history);
```
