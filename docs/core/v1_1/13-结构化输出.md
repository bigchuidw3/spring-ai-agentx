# 结构化输出

v1_1 下的结构化输出能力仍然是“单次调用级配置”，但它已经和当前会话持久化自然兼容。

## 1. 先理解它的边界

结构化输出只作用于当前这一次非流式调用。

也就是说：

- 同一个 `ReactAgent` 实例可以复用
- 同一个 `conversationId` 也可以复用
- 某一轮是普通自由文本，下一轮再切到结构化输出，完全没问题

控制入口仍然是：

- `RunnableParams.outputType(...)`

## 2. 为什么说它是 per-call 能力

`outputType` 放在 `RunnableParams` 里，而不是放在 `ReactAgent.Builder` 里，这意味着它天然是“本次调用是否要求 JSON 输出”的开关。

典型用法就是：

1. 第一轮正常聊天，先把上下文建立起来
2. 第二轮在同一会话里要求结构化输出
3. 仍然沿用同一个 `conversationId`

这样做的好处是：

- 普通对话负责补足上下文
- 结构化输出只在真正需要 JSON 时才打开
- 不会把整个 Agent 永久锁死成 JSON 模式

## 3. 与当前会话记忆的关系

v1_1 下，结构化输出不会绕开当前会话持久化。

它与会话状态的关系是：

- 本轮调用前，历史仍按正常规则加载
- 优先加载 `working_messages`
- 为空时回退 `original_messages`
- 本轮完成后，新增消息仍会落入当前会话状态

所以结构化输出并不是“单独的一条旁路能力”，而是建立在当前会话状态之上的一种回答格式。

## 4. 一个很常见的使用模式

最典型的场景就是：

- 上一轮用户先给背景信息
- 下一轮要求按 JSON 输出总结结果

例如：

1. 第一轮：用户说“请记住我的项目技术栈偏好：Java 21、Spring Boot、MySQL、Redis、Kubernetes”
2. 第二轮：用户说“基于我刚才给你的技术栈偏好，按 JSON 输出 language、framework、database、cache、deployment、summary”

这两轮完全可以共用同一个 `conversationId`。

## 5. 典型写法

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .maxRounds(6)
        .build();

RunnableParams plainParams = RunnableParams.builder()
        .conversationId(convId)
        .userId(userId)
        .build();

RunnableParams structuredParams = RunnableParams.builder()
        .conversationId(convId)
        .userId(userId)
        .outputType(ProjectStackSummary.class)
        .build();

agent.callForResult("先记住我的技术栈偏好", plainParams);
agent.callForResult("基于刚才的偏好按 JSON 输出", structuredParams);
```

这里最关键的是：

- `conversationId` 一样
- 第一轮没有 `outputType`
- 第二轮才设置 `outputType(ProjectStackSummary.class)`

## 6. 为什么只推荐非流式场景

结构化输出当前仍然主要面向非流式调用：

- `call()`
- `callForResult()`

原因很简单：

- 流式输出是逐段文本增量返回
- JSON 在中间分片阶段通常是不完整的
- 调用方很难在流式片段阶段做稳定反序列化

所以在需要可靠 JSON 的场景下，优先使用非流式调用更稳妥。

## 7. 如何定义输出类型

结构化输出的目标类型通常是一个标准 POJO。

```java
public static class ProjectStackSummary {
    @JsonProperty("language")
    private String language;

    @JsonProperty("framework")
    private String framework;

    @JsonProperty("database")
    private String database;

    @JsonProperty("cache")
    private String cache;

    @JsonProperty("deployment")
    private String deployment;

    @JsonProperty("summary")
    private String summary;
}
```

实践上建议：

- 保持字段名清晰稳定
- 提供无参构造器
- 用 Jackson 注解明确 JSON 字段

## 8. 返回结果怎么处理

结构化输出返回的仍然是字符串，只不过它应该是合法 JSON。

调用方通常自己反序列化：

```java
AgentResult result = agent.callForResult(query, structuredParams);
if (result instanceof AgentResult.Completed c) {
    ProjectStackSummary summary = objectMapper.readValue(c.answer(), ProjectStackSummary.class);
}
```

## 9. 推荐用哪个样例验证

### `StructuredOutputSessionTest`

这个样例直接证明了三件事：

1. 同一会话中，上一轮可以先走普通回答
2. 下一轮可以切到 `RunnableParams.outputType(...)`
3. 结构化输出与 `agentx_conversation` / `agentx_session` 落库兼容

如果你要验证“结构化输出是不是会破坏当前会话记忆”，这个样例就是最直接的入口。

## 10. 小结

这一版最重要的口径只有三条：

- `RunnableParams.outputType(...)` 仍然是单次调用级配置
- 同一会话里可以先普通对话，再切结构化输出
- 结构化输出建立在当前会话持久化之上，不是独立的特殊通道
