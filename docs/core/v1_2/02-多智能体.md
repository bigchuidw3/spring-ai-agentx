# 02 - 多智能体

agentx 在 ReactAgent 运行时之上提供多智能体能力：master 可以把子任务委派给子 Agent（子 Agent 就是一个普通 ReactAgent），支持**提前构建**与**运行时动态派生**两种模式。子 Agent 具备跨调用的多轮记忆、独立可观测性与中断恢复。

## 相比之前版本的升级

v1_0 / v1_1 的 SubAgent（见 [v1_0_M2 版本文档](../v1_0_M2/18-SubAgent子代理.md)、[v1_1 版本文档](../v1_1/18-SubAgent子代理.md)）是「无状态子代理」：子 Agent 有独立 context window，但 session 持久化永远关闭、不写自己的 `agentx_session`，父 Agent 才是会话持久化边界，也没有多轮记忆与独立中断恢复。

v1_2 把它升级为「有状态子代理」，核心变化：

| 维度 | v1_0 / v1_1 | v1_2 |
|---|---|---|
| 会话持久化 | 子 Agent 关闭 session，父为唯一边界 | 子 Agent 独立 `agentx_session` 分区（按 `agent_key`） |
| 多轮记忆 | 无（每次调用新实例） | 跨调用多轮记忆，记忆键 `(conversation_id, agent_key)` |
| 子 Agent 形态 | 仅预定义 `call_{name}` | 预定义 `call_{name}` + 动态派生 `spawn_subagent` |
| 轨迹审计 | 复用父 TraceStore，无 agent 维度 | `agentx_trace` 带 `agent_key`，各 agent 独立还原执行序列 |
| 中断恢复 | 不支持独立快照/恢复，由父统一承担 | 子 Agent 独立快照（children）+ 广播中断 + 流式续跑 |
| 父子溯源 | 无 | `parent_session_id` / `parent_tool_call_id` 两列精确溯源 |

## 1. 表模型改动

多智能体引入 `agent_key` 维度分区、`parent_session_id` / `parent_tool_call_id` 父子溯源列，以及 `created_at` 入库时间的线性化调整，详见 [01 - 表结构变更与字段调整](01-表结构变更与字段调整.md)。

要点：

- `agentx_session`：加 `agent_key` / `parent_session_id` / `parent_tool_call_id` 三列 + 分区索引，三态按 `agent_key` 分区读写
- `agentx_trace`：加 `agent_key` / `parent_tool_call_id` 两列 + 索引
- `created_at`：`original_messages` 每条消息用生成时刻（线性时间），`working_messages` 用本次调用开始时间统一打点

## 2. 关联关系

### 2.1 身份模型

| 字段 | 语义 | 稳定性 |
|---|---|---|
| `conversation_id` | 会话窗口，用户与 master 的多轮线程 | 稳定，所有 agent 共享 |
| `agent_key` | 消息/轨迹归属：`master` / 子 agent 名 | 稳定 |
| `session_id` | 本次调用 ID；master 与 subagent 一视同仁，每次调用都换 | 每次调用变化，纯溯源元数据 |

**记忆连续性键 = `(conversation_id, agent_key)`**。子 Agent 的记忆与 master 记忆完全同构，都挂在这个键上。`session_id` 不是记忆键，不复用为「稳定子会话」；由此，续接子 Agent 不需要父 LLM 传任何句柄，同会话内同名即自动续接。

### 2.2 父子溯源

| 字段 | 语义 |
|---|---|
| `parent_session_id` | 属于哪次 master 调用（聚合统计用） |
| `parent_tool_call_id` | 由 master 哪一步 ToolCall 派生（精确顺序溯源） |

父子关联链：`master.ToolCall.id == master.ToolResponse.id == subagent.parent_tool_call_id`。master 分区内 ToolCall 的 `item_index` 即派生时机。

### 2.3 ID 对齐

`SubAgentSource.subAgentId`（流式事件）= `agentx_session.session_id`（消息链）= `agentx_trace.session_id`（轨迹），三处用同一 ID，可互相关联跳转。

## 3. agentKey 身份规则

`agentKey` 是分区归属，记忆键为 `(conversation_id, agent_key)`。设置规则：

| 场景 | agentKey 取值 | 如何设置 |
|---|---|---|
| master | `"master"`（默认） | `Builder.agentKey(...)` 可改，通常不改 |
| 预定义子 Agent | 自动 = `name` | 框架注入，无需手动 |
| 动态派生子 Agent | 自动 = `name` | 框架注入，无需手动 |

两种模式的子 Agent 都由框架自动把 `agentKey` 设为 `name`。调用方若显式设置 `Builder.agentKey(...)`（非 `"master"`），框架保留该自定义值。一般业务不需要手动改 master 的 `agentKey`。

## 4. 两种模式

| 模式 | 触发方式 | 生成的工具 | 子 Agent 何时确定 |
|---|---|---|---|
| 预定义子 Agent | `ReactAgent.builder().subAgent(...)` | `call_{name}` | 构建 master 时提前声明 |
| 动态派生子 Agent | `SubAgentTool.createDynamic(...)` | `spawn_subagent` | 运行时由 master LLM 给定 name + task |

### 4.1 预定义子 Agent

在 master 的 `Builder` 上注册 `subAgent(Supplier<ReactAgent>)`，子 Agent 必须设置 `name` 和 `description`。

```java
ReactAgent pm = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .thinkingMode(ThinkingMode.REASONING_CONTENT)
        .instructions("你是研发项目经理。遇到需求分析任务必须调用 call_requirement-analyst 委派，不要自己直接分析。")
        .subAgent(() -> ReactAgent.builder()
                .name("requirement-analyst")                       // 必须：工具名 call_requirement-analyst，同时是 agentKey
                .description("需求分析师，把模糊需求拆解为结构化需求说明") // 必须：写进工具描述供 master LLM 决策
                .chatModel(chatModel)
                .instructions("你是需求分析师。把需求拆解为功能点、约束、验收标准。")
                .maxRounds(10)
                .build())
        .maxRounds(20)
        .build();

pm.streamForResult("请分析需求：实现手机号+验证码登录", params).blockLast();
```

- `build()` 先调用一次每个 supplier 提取 `name`/`description` 元数据；每次实际委派再 `provider.get()` 创建新实例（线程安全）。
- 子 Agent 自动复用父的 `SessionMessageStore` / `TraceStore`，按 `agentKey` 分区读写。

### 4.2 动态派生子 Agent

用 `SubAgentTool.createDynamic(agentFactory)` 生成 `spawn_subagent` 工具，挂到 master。工具描述有内置默认值，需要自定义时用 `createDynamic(description, agentFactory)` 重载。

```java
ToolCallback spawnSubAgent = SubAgentTool.createDynamic(
        req -> ReactAgent.builder()
                .chatModel(chatModel)
                .dataSource(dataSource)
                .thinkingMode(ThinkingMode.REASONING_CONTENT)
                .tools(regularTools)         // 只带普通工具，不含 spawn_subagent / call_*
                .maxRounds(30));             // 返回 Builder，name/instructions/agentKey 由框架自动设置

ReactAgent master = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .instructions("你是总控。可以把子任务派发给临时子 Agent 并行处理，最后汇总。")
        .tools(spawnSubAgent)                // 挂载 spawn_subagent
        .maxRounds(20)
        .build();
```

`spawn_subagent` 入参：`name`（子 Agent 名称，唯一键）+ `task`（任务描述）。框架自动把 `name` 设为子 Agent 名、`task` 设为子 Agent `instructions`、`agentKey` 设为 `name`。调用方只需在 `agentFactory` 里填差异项（模型、工具、轮次等）。无 `session_id` 入参，续接靠 `name`。

需要固定子 Agent 身份或提示词时，在 `agentFactory` 里显式设置 `.name(...)` / `.instructions(...)`，框架会保留调用方的值，不再用 LLM 传入的 `name` / `task` 覆盖（固定 name 意味着每次派生都续接同一个子 Agent 的记忆）：

```java
SubAgentTool.createDynamic(
        req -> ReactAgent.builder()
                .name("文档助手")               // 固定 name，忽略 LLM 传的 req.name()
                .instructions("你是文档处理专家…") // 固定 instructions，忽略 req.task()
                .chatModel(chatModel)
                .tools(regularTools)
                .maxRounds(30));
```

### 4.3 模式差异

| 维度 | 预定义 | 动态派生 |
|---|---|---|
| 子 Agent 身份 | 构建时固定 | 运行时由 LLM 决定 |
| agentKey 注入 | 自动 = name | 自动 = name |
| SessionMessageStore | 复用父的 | 自建（同一 dataSource，同表分区） |
| 适用场景 | 角色固定、数量有限的团队 | 临时、未知、并行的子任务 |

## 5. 约束清单

子 Agent（两种模式通用）：

- 必须设置 `name`（预定义还须 `description`）；
- 禁止嵌套：子 Agent 不能再包含 `SubAgentTool`（`spawn_subagent` / `call_*`）；
- 禁止 `AskUser`：子 Agent 不与用户直接交互；
- 禁止 `PauseAdvisor`：子 Agent 不暂停等人工。

`assertAllowed` 在委派前校验，违反直接抛异常。

## 6. 记忆与续接语义

- **记忆键 = `(conversation_id, agent_key)`**，`agentKey` 即 `name`。
- **同名续接**：同一会话内再次调用同名子 Agent，自动加载该分区历史，接着上次继续。
- **异名新建**：换个 name 就是全新分区，从零开始。
- `session_id` 每次委派自动生成，仅用于 trace 溯源与 `parent_session_id` 关联，不参与记忆加载。

示例：master 第一次派生 `desktop-lister` 跑了一半被中断，恢复后再次派生同名 `desktop-lister`，它会自动加载上次的 working_messages（含 TodoWrite 状态、已执行的工具结果），接着干而不是从头来。

## 7. 中断与恢复

- 中断：`master.interrupt(conversationId, message)` 广播中断所有运行中的子 Agent 并中断 master 自己。
- 快照：master 的 `PauseState` 以 `children` 携带各子 Agent 快照（含 `agentKey`、`parentToolCallId`）。
- 恢复：`master.resumeStream(conversationId)`。

| 恢复方式 | 触发 | 行为 |
|---|---|---|
| 纯续跑 | `resumeQuery` 为空 | 子 Agent 从快照流式续跑，master 不重新推理 |
| 带新指令 | 用户带了新消息 | master 重新决策（重新 spawn），子 Agent 按 name 续接工作链 |

前端若需「无缝恢复」，提供一个不带消息的「继续」入口（传空 `resumeQuery`）即可触发纯续跑，不要在后端写死「继续」等关键词。

## 8. 流式输出与前端展示

子 Agent 的流式事件带 `source`（`SubAgentSource{agentName, subAgentId}`），`subAgentId` 与 `session_id` / `agentx_trace.session_id` 对齐。前端据此把子 Agent 的思考/正文/工具事件归入独立的「SubAgent」面板，与 master 时间线区分。

## 9. 可观测性

子 Agent 的可观测性分两条通道：

- **自建审计（`agentx_trace`）**：子 Agent span 带 `agent_key` / `parent_tool_call_id`，轨迹页签可按 `(conversation_id, agent_key)` 独立还原每个 Agent 的执行序列，并把子 Agent span 挂到 master 的 `spawn_subagent` 工具下。
- **OTel（`TracingHook`）**：调用方只需在 master 的 builder 上配置一次 `.tracer(tracer)`，子 Agent 无需手动挂 `TracingHook`，框架自动复用父的 `Tracer` 产出可观测性 span（`agentx_<conversationId>` 根 span + 轮次/工具 span）。若子 Agent 显式配置了 `TracingHook`，则以子 Agent 的为准。

```java
ReactAgent master = ReactAgent.builder()
        .chatModel(chatModel)
        .tracer(tracer)               // master 配一次，子 Agent 自动复用
        .subAgent(() -> ReactAgent.builder()   // 子 Agent 无需再配 tracer / TracingHook
                .name("researcher").description("研究员").chatModel(chatModel)
                .instructions("...").build())
        .build();
```

## 10. 完整示例

```java
// 预定义三个专职子 Agent 的研发团队
ReactAgent pm = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .thinkingMode(ThinkingMode.REASONING_CONTENT)
        .instructions("你是研发项目经理。按需协调需求分析师、开发工程师、测试工程师。")
        .subAgent(() -> ReactAgent.builder()
                .name("analyst").description("需求分析师").chatModel(chatModel)
                .instructions("拆解需求为功能点、约束、验收标准。").maxRounds(10).build())
        .subAgent(() -> ReactAgent.builder()
                .name("developer").description("开发工程师").chatModel(chatModel)
                .instructions("输出技术选型与关键接口。").maxRounds(10).build())
        .subAgent(() -> ReactAgent.builder()
                .name("tester").description("测试工程师").chatModel(chatModel)
                .instructions("输出关键测试用例。").maxRounds(10).build())
        .maxRounds(20)
        .build();

RunnableParams params = RunnableParams.builder()
        .conversationId(conversationId)
        .userId(userId)
        .build();

// 流式执行
pm.streamForResult("实现用户登录功能", params)
        .doOnNext(System.out::println)
        .blockLast();

// 中断
pm.interrupt(conversationId, "用户主动中断");

// 恢复（纯续跑）
pm.resumeStream(conversationId).blockLast();
```
