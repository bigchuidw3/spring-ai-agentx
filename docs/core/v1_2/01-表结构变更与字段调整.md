# 01 - 表结构变更与字段调整

本篇汇总 v1_2 引入的表结构变更与字段语义调整，含多智能体的 `agent_key` 分区字段，以及 `created_at` 入库时间的线性化调整。

## 1. agentx_session

```sql
ALTER TABLE agentx_session
    ADD COLUMN agent_key VARCHAR(100) NOT NULL DEFAULT 'master' COMMENT '消息归属: master / 子agent名',
    ADD COLUMN parent_session_id VARCHAR(100) DEFAULT NULL COMMENT '父master调用的session_id',
    ADD COLUMN parent_tool_call_id VARCHAR(100) DEFAULT NULL COMMENT '派生出本subagent调用的ToolCall id';

CREATE INDEX idx_conv_agent_state ON agentx_session (conversation_id, agent_key, state_key);
```

- 存量行 `agent_key` 回填 `'master'`，旧数据行为不变。
- `item_index` 语义变为「`(conversation_id, agent_key, state_key)` 分区内有序」，各 agent 独立编号。
- 三态（`original_messages` / `working_messages` / `offload_context`）均按 `agent_key` 分区读写。

## 2. agentx_trace

```sql
ALTER TABLE agentx_trace
    ADD COLUMN agent_key VARCHAR(100) NOT NULL DEFAULT 'master' COMMENT 'master / 子agent名',
    ADD COLUMN parent_tool_call_id VARCHAR(100) DEFAULT NULL COMMENT '派生本subagent调用的ToolCall id';

CREATE INDEX idx_agentx_trace_conv_agent ON agentx_trace (conversation_id, agent_key);
```

- 存量行回填 `'master'`。
- 每个 agent 的 LLM/TOOL/COMPACT Span 用自身 `agent_key` 标记，`countTools / countToolFailures` 维持按 `session_id` 计数，子 Agent Span 用自己的 `session_id`，不污染 master 统计。

## 3. 不变的表

| 表 | 说明 |
|---|---|
| `agentx_conversation` | 子 Agent 不写行；`rounds / tool_calls / tokens` 统计保持 master 视角 |
| `agentx_pause_state` | `PauseState.children` 已支持携带子 Agent 快照，结构不变 |

## 4. created_at 入库时间调整

### 4.1 调整前的问题

消息在终态落库时，**统一用「落库时刻」打点 `created_at`**（`persistOnTerminal` 时取一次 `now`）。后果是：同一次调用内新增的所有消息 `created_at` 完全相同，历史会话回放时只能看到一堆「同一时间」的消息，无法还原消息的先后顺序，也对应不到执行时序。

### 4.2 调整后

新增 `TimedMessage(Message message, LocalDateTime createdAt)`，把每条消息与其生成时刻绑定。

- `AgentRuntimeContext` 维护 `originalMessagesSnapshot`（`List<TimedMessage>`）：
  - `appendOriginalMessage` 每次追加时用 `LocalDateTime.now()` 打点，即**消息生成时刻**；
  - 加载进来的历史消息（`setOriginalMessagesSnapshot`）统一用「本次加载时刻」打点（原始时间已不可知）。
- 落库时分两条口径：
  - `original_messages`：用 `TimedMessage.createdAt`（每条消息自己的生成时刻），`created_at` **线性递增**，可还原消息先后顺序与执行时序；
  - `working_messages`：用 `callStartedAt`（本次调用开始时间）统一打点，压缩演进覆盖写时不改写历史消息的原始时间。

### 4.3 为什么改

之前所有消息时间一样，回放时看不出先后；改成每条消息用生成时刻后，`created_at` 呈线性递增，历史会话回放与轨迹对齐更清晰、更直观。

## 5. 迁移与兼容

1. 变更通过各 Store 的 `ensureInitialized` 内 `ALTER TABLE` 幂等执行（表已存在补列、列已存在跳过），与既有迁移方式一致。
2. 升级顺序：先执行表变更，再部署新代码。旧代码写入的行 `agent_key='master'`，新代码读取不受影响。
3. 回滚：新列均可置空/默认值，旧版本代码忽略新列即可回退。
