# 03 - 可观测性

基于 OpenTelemetry 标准，把 Agent 调用链输出为完整 trace 树，对接任意支持 OTLP 的观测平台（Opik / Langfuse / Tempo / Jaeger 等，换后端只改 endpoint）。v1_2 起，子 Agent 纳入同一棵 trace 树，调用方接入也更简单。

## 相比之前版本的升级

| 维度 | v1_1_M2 | v1_2 |
|---|---|---|
| TracingHook 挂载 | 手动 `.hooks(new TracingHook(tracer))` | `.tracer(tracer)` 自动挂载 |
| 子 Agent 观测 | 无（只有 master 的 trace） | 子 Agent 独立根 span，挂到 master 工具下 |
| 子 Agent tracer | 无 | 自动复用 master 的 tracer，无需手动挂 |
| LLM span 内容 Handler | 调用方手动注册 | 框架内置自动注册 |

核心变化一句话：**调用方只配 `.tracer(tracer)` + `.observationRegistry(observationRegistry)` 两处，其余（TracingHook 挂载、`ChatContentObservationHandler` 注册、子 Agent 复用）由框架自动完成**。

## 1. span 树结构

一次 `call()` / `stream()` 调用在观测平台上的 span 树（含子 Agent）：

```
agentx_<conversationId>          ← master 根 span
├─ agentx.round.N.*              ←   每轮 prompt / output / tool_calls 原文
├─ chat <模型名>                 ←   LLM span：模型名 / token / 耗时 / input / output
├─ agentx.tool.<工具名>          ←   工具 span：参数 / 结果 / 成败 / 耗时
├─ agentx.compact                ←   上下文压缩 span：strategy / 前后 token / 消息数 / 耗时
└─ agentx_<子Agent名>            ←   子 Agent 根 span（v1_2 新增，用 agentKey 命名）
   ├─ agentx.round.N.*
   ├─ chat <模型名>
   └─ agentx.tool.<工具名>
```

| 想看什么 | 看哪里 |
|----------|--------|
| 用户问题 / 每轮收发原文 / 工具调用指令 / 最终答案 / token 汇总 | 根 span 的 Input 标签页 |
| 某一轮的模型名 / token / 耗时 / 原文 | `chat <模型名>` span |
| 工具的参数与结果 | `agentx.tool.*` 的 Input / Output |
| 上下文压缩的策略与前后规模 | `agentx.compact` span |
| 子 Agent 的独立执行过程 | `agentx_<子Agent名>` 根 span |
| 按用户 / 会话过滤，或从日志反查 | Metadata：`userId` / `conversationId` / `otelTraceId` |

> 上下文压缩在 OTel 的呈现：L1-L3（工具列表压缩 / 大消息卸载，不调 LLM）只产出一条 `agentx.compact`；L4-L6（历史轮次 / 当前轮摘要）还会额外有一条 `chat <模型名>` 摘要调用 span。二者平级挂在根 span 下（非父子）——这是 OTel「span 出生即定父」的机制限制：摘要 LLM 的 span 在调用现场就生成了，晚一步创建的 `agentx.compact` 无法成为它的父。若需要完整父子结构（COMPACT 为父、摘要 LLM 为子），`agentx_trace` 自建表用显式 `compact_id` 关联、天然支持，可基于它做更精确的调用链查询与结构化展示。

## 2. 接入步骤

### 2.1 加依赖

```xml
<!-- 版本均由 Spring Boot BOM 管理，无需写版本号 -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-otel</artifactId>
</dependency>
<dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-exporter-otlp</artifactId>
</dependency>
```

引入即自动装配 `ObservationRegistry` 和 `Tracer`（Spring Boot 自动配置，无需手动创建 Bean）。

### 2.2 配置导出目标（application.yml）

```yaml
management:
  tracing:
    sampling:
      probability: 1.0          # 采样率，全量；生产可调低
  otlp:
    tracing:
      endpoint: https://www.comet.com/opik/api/v1/private/otel/v1/traces   # 平台 OTLP 地址（完整 URL）
      headers:                  # 按平台要求配置
        Authorization: <api-key>
        Comet-Workspace: <workspace>   # Opik 需要；其他平台按各自要求
        projectName: <project>         # Opik 路由到项目；其他平台可省略
```

> 自建 Opik 的 OTLP 路径与云端一致（`/api/v1/private/otel/v1/traces`），仅 host 不同；不带云端专用的 `Authorization` / `Comet-Workspace`。

### 2.3 构建 ReactAgent

`observationRegistry` 和 `tracer` 都从 Spring 容器直接注入。核心就两行：`.observationRegistry(...)` 管 LLM span，`.tracer(...)` 管 Agent 结构 span（根 + 工具 + 子 Agent）。

```java
@Bean
public ReactAgent agent(ChatModel chatModel,
                        ObservationRegistry observationRegistry,
                        Tracer tracer) {
    return ReactAgent.builder()
            .chatModel(chatModel)
            .observationRegistry(observationRegistry)   // LLM span（chat <模型名>）
            .tracer(tracer)                             // Agent 结构 span（根 + 工具 + 子 Agent）
            .dataSource(dataSource)                     // 可选：启用自建 trace 审计存储
            .tools(BashTool.create())
            .build();
}
```

> v1_2 起不用再手动 `.hooks(new TracingHook(tracer))`：`.tracer(tracer)` 会让框架自动挂 `TracingHook`，并透传给子 Agent。

### 2.4 观测降噪（可选）

`ChatContentObservationHandler`（LLM span 的 input/output 原文）由框架自动注册，调用方无需手动配置。`ObservationPredicate` 用于过滤 HTTP/JDBC/定时任务等框架噪声，属于调用方可选的降噪配置：

```java
@Configuration
public class ObservabilityConfig {

    /** 降噪：只保留 Agent/LLM 观测 */
    @Bean
    public ObservationPredicate observationPredicate() {
        return ObservabilityPredicates.agentOnly();
    }
}
```

### 2.5 调用时传 userId / conversationId

```java
RunnableParams params = RunnableParams.builder()
        .conversationId("conv_001")   // 会话窗口标识
        .userId("42")                 // 用户标识：写入 trace 元数据，实现数据隔离
        .build();

String answer = agent.call("帮我分析这个文件", params);
```

传了 `userId` 后，观测平台按 `opik.metadata.userId` 过滤即可只看该用户的链路。

## 3. 完整接入示例

```java
@Configuration
public class AgentObservabilityConfig {

    @Bean
    public ObservationPredicate observationPredicate() {
        return ObservabilityPredicates.agentOnly();
    }

    @Bean
    public ReactAgent agent(ChatModel chatModel,
                            ObservationRegistry registry,
                            Tracer tracer,
                            DataSource dataSource) {
        return ReactAgent.builder()
                .chatModel(chatModel)
                .observationRegistry(registry)
                .tracer(tracer)
                .dataSource(dataSource)          // 可选：启用自建审计存储（agentx_trace 等三张表自动建）
                .tools(BashTool.create())
                .build();
    }
}
```

调用：

```java
RunnableParams params = RunnableParams.builder()
        .conversationId(conversationId)
        .userId(userId)
        .build();
Flux<AgentStreamEvent> stream = agent.streamForResult(question, params);
```

## 4. 子 Agent 可观测性

子 Agent 的 OTel 观测只需在 master 的 builder 上配一次 `.tracer(tracer)`，子 Agent 无需手动挂 `TracingHook`，框架自动复用父的 `Tracer`。子 Agent 根 span 用 `agentx_<agentKey>` 命名（区别于 master 的 `agentx_<conversationId>`），挂到 master 的 `spawn_subagent` / `call_<name>` 工具 span 下。

```java
ReactAgent master = ReactAgent.builder()
        .chatModel(chatModel)
        .observationRegistry(observationRegistry)
        .tracer(tracer)                          // 配一次，子 Agent 自动复用
        .subAgent(() -> ReactAgent.builder()     // 子 Agent 无需再配 tracer / TracingHook
                .name("researcher").description("研究员").chatModel(chatModel)
                .instructions("...").build())
        .build();
```

子 Agent 的自建审计（`agentx_trace`）按 `(conversation_id, agent_key)` 分区，详见 [02 - 多智能体](02-多智能体.md)。

## 5. 排查指引

- **只有根 span、没有 `chat <模型名>`**：检查 ChatModel 是否传了 `observationRegistry`（模型构建处 + ReactAgent 的 `.observationRegistry(...)` 都要传）；没传则 Spring AI 的 observation 不生效，LLM span 不产出。
- **有 `chat <模型名>` 但没有 input/output 原文**：`ChatContentObservationHandler` 由框架自动注册，通常无需处理；若被调用方自定义 Bean 覆盖，检查该 Bean 是否正确。
- **只有根 span、没有工具 span**：检查是否传了 `.tracer(tracer)`；没传则 `TracingHook` 未挂载，工具 span 不产出。
- **出现了独立的 trace**：未走框架构建的 LLM 调用（调用方自行 new ChatClient）会脱离主树独立成 trace，应统一走 ReactAgent 的 ChatClient。
- **日志与 trace 互查**：应用日志方括号内的 traceId 即 `opik.metadata.otelTraceId`，在平台按该值检索直接定位对应 trace。
