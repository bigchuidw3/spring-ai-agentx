# 分层记忆体系

框架提供三层记忆架构，按生命周期和粒度分层管理，让 Agent 具备"记住"能力：

```
┌─────────────────────────────────────────────────┐
│ 短期记忆 (agentx_session)                          │
│ 按 conversationId 维度，当前会话的最近 N 轮问答      │
│ 自动加载 / 自动保存 / 轮数 & token 双重限制          │
├─────────────────────────────────────────────────┤
│ 会话摘要 (session_summary)                         │
│ 同会话溢出压缩，将超出短期记忆窗口的历史轮次          │
│ 增量合并 / 步长节流 / 按 conversationId 隔离         │
├─────────────────────────────────────────────────┤
│ 全局知识 (cross_summary)                           │
│ 跨会话提炼的可复用知识，按 userId 维度               │
│ 语义检索 / 时间戳水位线 / 承担用户画像职能           │
└─────────────────────────────────────────────────┘
```

## 三层记忆对比

| 层级 | 存储方式 | 维度 | 注入方式 | 典型用途 |
|------|---------|------|---------|---------|
| 短期记忆 | 关系型数据库（JSON） | conversationId | 确定性加载（最近 N 轮） | 当前对话上下文 |
| 会话摘要 | 向量数据库 | conversationId | 语义检索（topK=5） | 长会话历史压缩 |
| 全局知识 | 向量数据库 | userId | 语义检索（topK=5） | 跨会话知识、偏好、决策 |

## 语义记忆三层子结构

长期/语义记忆（`agent_semantic_memory`）内部有三类文档，分工明确：

```
┌──────────────────────────────────────────────┐
│ qa_pair — 原始 Q&A，永不修改/删除              │
│ 按 created_at 升序，是摘要的原材料              │
├──────────────────────────────────────────────┤
│ cross_summary — 跨会话全局知识                 │
│ 从 qa_pair 中提炼可复用知识，水位线推进         │
│ 承担用户画像职能（偏好、背景、决策）            │
│ 触发阈值 15 条（可配），每批 5 条分批摘要       │
├──────────────────────────────────────────────┤
│ session_summary — 同会话溢出压缩               │
│ 当会话轮数超过 maxHistoryRounds 时增量合并      │
│ 步长节流防止频繁触发（默认 step=5）            │
└──────────────────────────────────────────────┘
```

### 文档类型标识

| 常量 | 值 | 说明 |
|------|---|------|
| `DOC_TYPE_QA` | `"qa_pair"` | 原始问答对 |
| `DOC_TYPE_CROSS_SUMMARY` | `"cross_summary"` | 跨会话全局知识摘要 |
| `DOC_TYPE_SESSION_SUMMARY` | `"session_summary"` | 同会话溢出摘要 |

### 检索策略

每次对话前，分别检索两类记忆，注入到 SystemMessage 的不同区块：

- **cross_summary**：`searchCrossSummary(userId, query, topK=5)` — 按 userId 语义检索相关全局知识
- **session_summary**：`getSessionSummary(conversationId)` — 按 conversationId 精确查找（最多一条，不需要语义检索）

```
SystemMessage:
  ├─ instructions (核心行为 prompt)
  ├─ 跨会话全局知识 (## 跨会话全局知识)
  │     - searchCrossSummary 检索结果，topK=5
  ├─ 当前会话历史摘要 (## 当前会话历史摘要)
  │     - getSessionSummary 精确查找结果
  ├─ 自定义参数
  └─ 工具/任务引导
```
  ├─ 自定义参数
  └─ 工具/任务引导
```

### cross_summary 时间戳水位线

用 `latest_qa_created_at` 追踪进度，而非存储 qa_ids（避免膨胀）：

- 每条 cross_summary 记录它所处理 qa_pair 的最大 `created_at`
- 水位线 = max(所有 cross_summary 的 `latest_qa_created_at`)
- qa_pair 的 `created_at > 水位线` 即为"未处理"
- qa_pair 本身**永不修改、永不删除**

```
qa_pair 时间线：  [1] [2] [3] ... [15] [16] [17] ... [30] [31] [32] ...
                     ← 已处理（水位线=15）→ | ← 未处理 →
                                         触发摘要：取 16~30 共 15 条
```

### cross_summary 的内容标准（严格）

cross_summary 存储「下次对话还能用上的知识」，不是「本次对话的执行记录」：

**应该提取**：用户偏好/习惯/背景、项目架构/技术栈、重要决策及原因、业务规则、文件路径/配置方式

**不应该提取**：简单运算（1+1）、临时调试、工具调用结果、闲聊寒暄、一次性普通问答

当无法判断时，宁可返回空也不要存垃圾。

### session_summary 增量合并与步长节流

每次只取**新增**溢出 qa_pair（上次已摘要的跳过），与已有 session_summary 合并：

```
maxHistoryRounds=30, step=5:

第35轮: overflow=5, 无旧摘要 → 压缩 qa[0..5) → A (source_count=5)
第40轮: overflow=10, 找到 A(source_count=5) → 合并 A + qa[5..10) → B (source_count=10)
第45轮: overflow=15, 找到 B(source_count=10) → 合并 B + qa[10..15) → C (source_count=15)
```

- **上下文有界**：每次 LLM 调用 = 1 条旧摘要 + 5 条新对话（不会随溢出量增长）
- **无重复摘要**：已处理的 qa_pair 通过 `source_count` 跳过
- **步长控制**：`sessionSummarizeStep` 默认 5，即 maxHistoryRounds=30 时，第 35/40/45... 轮才触发

## 上下文拼装流程

每次 `call/stream` 调用，`LoopMessageBuilder` 按以下顺序组装消息列表：

```
[0] SystemMessage (各段 \n\n 拼接):
    ├─ instructions (核心行为 prompt)
    ├─ 语义搜索结果 (cross_summary + session_summary, topK=5)
    ├─ 自定义参数 (RunnableParams.customParams)
    ├─ 工具搜索引导 (如有 deferredToolRegistry)
    └─ TodoWrite 引导 (如注册了 TodoWrite 工具)

[1] UserMessage       ← 历史 Q (最早)
[2] AssistantMessage  ← 历史 A
...
[N] AssistantMessage  ← 历史 A (最新)
[N+1] UserMessage     ← 当前 query + 格式要求
```

**短期记忆加载逻辑**：
1. 从 `agentx_session` 表查最近 `maxHistoryRounds`(默认30) 轮 Q&A（按时间升序）
2. 跳过空 answer 的行
3. 从最早的消息对开始，按 `maxHistoryTokens`(默认10000) 删除完整 Q&A 对

## 零配置模式

只需传入 DataSource，框架自动创建 `agentx_session` 表，管理短期记忆：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)                           // 自动创建会话表
        .build();

RunnableParams params = RunnableParams.builder()
        .conversationId("conv_001")
        .userId("user_123")
        .build();

String answer = agent.call("帮我分析这段代码", params);
// 框架自动：加载会话历史 → 语义检索 → 对话 → 保存会话 → 持久化记忆
```

### 自动执行流程

```
调用 call/stream
    │
    ├─ 1. 加载短期记忆（按 conversationId 从 agentx_session 加载最近 N 轮）
    ├─ 2. 语义检索长期记忆（按 userId + query 检索 cross_summary + session_summary）
    │
    ├─ 3. 组装 SystemMessage（指令 + 检索结果）
    │
    ├─ 4. 执行 Agent 循环（LLM 推理 + 工具调用）
    │
    ├─ 5. 保存短期记忆（将本轮问答 Upsert 到 agentx_session）
    └─ 6. 持久化语义记忆（qa_pair 入库 → 触发 cross_summary / session_summary 摘要）
```

## 启用长期记忆

长期记忆需要额外传入 VectorStore 和 EmbeddingModel：

```java
// 创建 VectorStore（以 PgVector 为例）
PgVectorStore vectorStore = PgVectorStore.builder(jdbcTemplate, embeddingModel)
        .dimensions(1024)
        .vectorTableName("agent_semantic_memory")
        .initializeSchema(true)
        .build();

// 创建 SemanticMemoryStore
SemanticMemoryStore semanticMemoryStore = new SemanticMemoryStore(vectorStore, embeddingModel);

// 配置 Agent
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .semanticMemoryStore(semanticMemoryStore)         // 长期记忆（可选）
        .maxHistoryRounds(30)                             // 短期记忆窗口大小
        .sessionSummarizeStep(5)                          // 会话摘要步长
        .build();
```

### 长期记忆配置项

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `summarizeThreshold` | 15 | cross_summary 触发阈值（qa_pair 条数） |
| `maxHistoryRounds` | 30 | 短期记忆窗口大小 + 会话摘要触发阈值 |
| `sessionSummarizeStep` | 5 | 会话摘要步长节流 |
| — | 5 | 每批 LLM 摘要的 qa_pair 数量 |
| — | 2000 | 每条 qa_pair 截断字符数 |
| — | 50 | 单次查询 qa_pair 最大数量 |

## 数据库表结构

### agentx_session（短期记忆）

| 列名 | 类型 | 说明 |
|------|------|------|
| id | BIGINT(20) | 主键（雪花算法） |
| conversation_id | VARCHAR(100) | 会话标识 |
| messages | TEXT | 对话消息（JSON 格式） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### agent_semantic_memory（长期记忆）

由 VectorStore 管理，包含三类文档：`qa_pair`、`cross_summary`、`session_summary`。

| 元数据字段 | 适用类型 | 说明 |
|-----------|---------|------|
| `type` | 全部 | 文档类型标识 |
| `user_id` | 全部 | 用户标识 |
| `conversation_id` | qa_pair, session_summary | 会话标识 |
| `created_at` | 全部 | 创建时间（qa_pair 用于水位线排序） |
| `latest_qa_created_at` | cross_summary | 水位线时间戳 |
| `source_count` | session_summary | 已摘要的 qa_pair 条数 |

## 精细控制开关

| 参数 | 控制 | 默认 | 说明 |
|------|------|------|------|
| `enableSession` | agentx_session（短期记忆） | `true` | 禁用后不加载会话历史，也不保存对话到数据库 |

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .enableSession(false)            // 无状态模式
        .build();
```

### 适用场景

| 场景 | 推荐配置 | 说明 |
|------|---------|------|
| 常规对话 Agent | 全部默认开启 | 完整记忆能力 |
| 一次性任务 Agent | `enableSession(false)` | 无状态，不残留历史 |

> 注意：以上开关仅对主 Agent 生效。子 Agent 始终关闭短期记忆。

## 短期记忆加载限制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxHistoryRounds` | 30 | 最大加载轮数，≤ 0 表示不限制 |
| `maxHistoryTokens` | 10000 | 估算 token 上限，≤ 0 表示不限制 |

两个限制独立生效：先按轮数查询，再按 token 从前往后截断完整 Q&A 对：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .maxHistoryRounds(30)     // 最多加载最近 30 轮
        .maxHistoryTokens(10000)  // 历史 token 累计超过 10000 时截断
        .build();
```

### 默认值建议

| 模型上下文 | 建议 maxHistoryRounds | 建议 maxHistoryTokens |
|-----------|----------------------|----------------------|
| 128k | 30 | 10000 |
| 64k | 20 | 6000 |
| 32k | 10 | 3000 |

超过轮数上限的历史对话不会丢失——它们会被 session_summary 压缩并存入向量库，通过语义检索在需要时自动注入。

## 最佳实践

1. **务必传入 conversationId 和 userId**：这是记忆体系工作的前提
2. **生产环境使用 JDBC**：内存存储重启后丢失，不适合生产
3. **长期记忆需要 EmbeddingModel**：选择与你的 LLM 兼容的 Embedding 模型
4. **合理设置 maxHistoryRounds 和 sessionSummarizeStep**：窗口太小上下文不足，太大则 token 消耗高；step 太小摘要频繁，太大则溢出积累过多
5. **无状态场景关闭 enableSession**：临时 Agent 或一次性任务避免历史污染
