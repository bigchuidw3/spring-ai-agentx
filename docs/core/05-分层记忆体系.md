# 分层记忆体系

框架提供三层记忆架构，按生命周期和粒度分层管理，让 Agent 具备"记住"能力：

```
┌─────────────────────────────────────────────────┐
│ 短期记忆 (agentx_session)                          │
│ 按 conversationId 维度，当前会话的问答历史           │
│ 自动加载 / 自动保存                                │
├─────────────────────────────────────────────────┤
│ 用户画像 (agentx_memory)                           │
│ 按 userId 维度，跨会话的结构化用户信息               │
│ LLM 自动提取 / 智能合并 / 自动去重                  │
├─────────────────────────────────────────────────┤
│ 长期记忆 (agent_semantic_memory)                  │
│ 按 userId 维度，向量化存储问答对和摘要               │
│ 语义检索 / 自动摘要压缩                            │
└─────────────────────────────────────────────────┘
```

## 三层记忆对比

| 层级 | 存储方式 | 维度 | 生命周期 | 典型用途 |
|------|---------|------|---------|---------|
| 短期记忆 | 关系型数据库（JSON） | conversationId | 单次会话 | 当前对话上下文 |
| 用户画像 | 关系型数据库 | userId | 跨会话持久 | 用户偏好、行为指令、客观事实 |
| 长期记忆 | 向量数据库 | userId | 跨会话持久 | 历史知识检索、QA 回忆 |

## 零配置模式

只需传入 DataSource，框架自动创建 `agentx_session` 和 `agentx_memory` 表，管理短期记忆和用户画像：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)                           // 自动创建会话表 + 用户画像表
        .build();

RunnableParams params = RunnableParams.builder()
        .conversationId("conv_001")
        .userId("user_123")
        .build();

String answer = agent.call("帮我分析这段代码", params);
// 框架自动：加载会话历史 → 注入用户画像 → 对话 → 保存会话 → 提取用户画像
```

### 自动执行流程

```
调用 call/stream
    │
    ├─ 1. 加载短期记忆（按 conversationId 从 agentx_session 加载最近 N 轮历史对话，受 maxHistoryRounds / maxHistoryTokens 限制）
    ├─ 2. 语义检索长期记忆（按 userId 从向量库检索相关知识）
    ├─ 3. 加载用户画像（按 userId 从 agentx_memory 加载结构化信息）
    │
    ├─ 4. 注入系统提示词（将记忆信息格式化后追加到 system prompt）
    │
    ├─ 5. 执行 Agent 循环（LLM 推理 + 工具调用）
    │
    ├─ 6. 保存短期记忆（将本轮问答保存到 agentx_session）
    ├─ 7. 提取用户画像（LLM 分析对话，提取用户信息，智能合并到 agentx_memory）
    └─ 8. 保存并压缩长期记忆（如有 SemanticMemoryStore，将 QA 对向量化存储，达到阈值时自动触发摘要合并）
```

## 启用长期记忆

长期记忆需要额外传入 VectorStore 和 EmbeddingModel，框架自动创建 `agent_semantic_memory` 向量表：

```java
// 创建 VectorStore（以 PgVector 为例）
PgVectorStore vectorStore = PgVectorStore.builder(jdbcTemplate, embeddingModel)
        .dimensions(1024)
        .vectorTableName("agent_semantic_memory")
        .initializeSchema(true)
        .build();

// 创建 SemanticMemoryStore
SemanticMemoryStore semanticMemoryStore = new SemanticMemoryStore(vectorStore, embeddingModel);

// 配置 Agent
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)                           // 短期记忆 + 用户画像
        .semanticMemoryStore(semanticMemoryStore)         // 长期记忆（可选）
        .build();

String answer = agent.call("之前我们讨论过的架构方案是什么", params);
// 框架自动：加载会话历史 → 注入用户画像 → 语义检索相关知识 → 对话 → 保存会话 → 提取画像 → 存入向量
```

### 长期记忆特性

- **QA 对存储**：每轮对话结束后，将问答对向量化存入 `agent_semantic_memory`
- **自动摘要压缩**：当 `qa_pair` 数量达到阈值（默认 15 条）时，自动用 LLM 分批生成摘要（每批 5 条），合并相关摘要防止无限增长
- **语义检索**：根据用户问题检索最相关的历史对话知识，注入到上下文中
- **文档类型**：`qa_pair`（原始问答对）和 `summary`（摘要文档）

## 使用不同存储后端

### JDBC（推荐生产环境）

```java
// 使用 Spring Boot 自动注入的 DataSource
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)         // 自动创建 agentx_session + agentx_memory 表
        .build();
```

### 内存（适合开发测试）

```java
// 不传 DataSource，使用内存存储（重启后丢失）
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .memoryStore(new InMemoryMemoryStore())   // 可选，默认即内存
        .build();
```

### 文件系统

```java
// JSON 文件存储，按 userId 分目录
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .memoryStore(new FileMemoryStore("/data/memories"))  // 指定存储目录
        .build();
```

## 数据库表结构

| 列名 | 类型 | 说明 |

| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### agentx_memory（用户画像）

| 列名 | 类型 | 说明 |
|------|------|------|
| id | BIGINT(20) | 主键（雪花算法） |
| user_id | VARCHAR(100) | 用户标识 |
| type | VARCHAR(20) | 记忆类型（PROFILE/PREFERENCE/INSTRUCTION/FACT） |
| content | TEXT | 记忆内容 |
| description | TEXT | 描述 |
| metadata_json | TEXT | 元数据（JSON） |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

索引：`idx_agentx_memory_user_id`、`idx_agentx_memory_user_type`

### agent_semantic_memory（长期记忆）

由 VectorStore 管理，存储向量化的 QA 对和摘要。

## 用户画像类型（agentx_memory）

| 类型 | 说明 | 提取示例 |
|------|------|---------|
| PROFILE | 用户画像 | "用户是一名 Java 开发工程师，5 年经验" |
| PREFERENCE | 用户偏好 | "偏好中文回答，喜欢简洁的代码风格" |
| INSTRUCTION | 行为指令 | "不要使用 var 关键字" |
| FACT | 客观事实 | "项目使用 JDK 21，Spring Boot 3.5" |

框架通过 LLM 自动从对话中提取用户画像，与已有信息智能合并：
- **新增**：全新信息直接添加
- **更新**：冲突信息以新为准（如偏好变化）
- **去重**：重复信息自动跳过

## MemoryTool — Agent 主动读写记忆

框架提供 `MemoryTool`，让 Agent 在对话过程中主动读取和保存记忆：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .tools(MemoryTool.create(memoryStore))    // 注册记忆工具
        .build();

// Agent 可以主动调用工具：
// - saveMemory：主动保存信息到用户画像
// - getMemory：读取用户的历史画像
// - searchMemory：语义搜索长期记忆
```

## 精细控制开关

Builder 提供两个开关，用于单独控制短期记忆和用户画像的启用与否。两个开关均默认为 `true`，只在主 Agent 生效。

| 参数 | 控制 | 默认 | 说明 |
|------|------|------|------|
| `enableSession` | agentx_session（短期记忆） | `true` | 禁用后不加载会话历史，也不保存对话到数据库 |
| `enableProfileMemory` | agentx_memory（用户画像） | `true` | 禁用后不注入用户画像，也不调用 LLM 提取画像 |

> 设计原则：`build()` 始终创建所有存储对象（轻量级、幂等），开关仅在**运行时写入点**生效。这样可以随时切换而无需重新构建 Agent。

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .enableSession(false)            // 不加载/保存短期记忆
        .enableProfileMemory(false)      // 不注入/提取用户画像
        .build();
```

### 适用场景

| 场景 | 推荐配置 | 说明 |
|------|---------|------|
| 常规对话 Agent | 全部默认开启 | 完整记忆能力 |
| 一次性任务 Agent | `enableSession(false)` | 无状态，不残留历史 |
| 成本敏感场景 | `enableProfileMemory(false)` | 省去画像提取的额外 LLM 调用 |
| 纯函数式 Agent | 两个都关 | 完全无状态，每次都是全新会话 |

### 与 trace 开关的关系

`enableTrace`（控制 agentx_trace 调用审计）属于另一个独立维度，详见 [TraceAudit 追踪审计](17-TraceAudit追踪审计.md#禁用-trace)。三个开关互不影响，可自由组合。

> 注意：以上开关仅对主 Agent 生效。子 Agent 的行为由框架自动配置（短期记忆和用户画像始终关闭），调用方无需设置。

## 短期记忆加载限制

当会话轮数积累过多时，全量加载历史对话会导致上下文窗口溢出。框架提供两个配置项控制历史加载量，保证不拆散单个 Q&A 对：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `maxHistoryRounds` | 30 | 最大加载轮数，≤ 0 表示不限制 |
| `maxHistoryTokens` | 10000 | 估算 token 上限，≤ 0 表示不限制 |

两个限制独立生效，先按轮数查询，再按 token 从前往后（最早的消息开始）截断完整 Q&A 对，保留最近的：

```java
ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)
        .maxHistoryRounds(30)     // 最多加载最近 30 轮
        .maxHistoryTokens(10000)  // 历史 token 累计超过 10000 时截断
        .build();
```

**全量加载（关闭限制）**：

```java
.maxHistoryRounds(0)
.maxHistoryTokens(0)
```

**Token 截断算法**：从最早的消息对开始删除，每次删除一组完整的 `(UserMessage, AssistantMessage)`，直到总 token 数不超上限。不会出现"14.5 轮"的情况。

### 默认值建议

| 模型上下文 | 建议 maxHistoryRounds | 建议 maxHistoryTokens |
|-----------|----------------------|----------------------|
| 128k | 30 | 10000 |
| 64k | 20 | 6000 |
| 32k | 10 | 3000 |

超过轮数上限的历史对话不会丢失——它们已存入向量库，通过语义检索在需要时自动注入。

## 长期记忆摘要阈值

SemanticMemoryStore 默认的摘要触发阈值为 15 条 Q&A，可通过构造函数自定义：

```java
SemanticMemoryStore store = new SemanticMemoryStore(vectorStore, embeddingModel, 20); // 20 条触发
```

摘要采用分批处理（每批 5 条 + 每条截断至 2000 字符），避免单次 LLM 调用超时。

## 最佳实践

1. **务必传入 conversationId 和 userId**：这是记忆体系工作的前提
2. **生产环境使用 JDBC**：内存存储重启后丢失，不适合生产
3. **长期记忆需要 EmbeddingModel**：选择与你的 LLM 兼容的 Embedding 模型
4. **记忆提取消耗额外 Token**：框架会在对话后额外调用 LLM 提取记忆，注意成本；若不需要可用 `enableProfileMemory(false)` 关闭
5. **无状态场景使用精细开关**：临时 Agent 或一次性任务可用 `enableSession(false)` 避免历史污染
6. **使用 MemoryTool 增强 Agent 记忆能力**：Agent 可以主动保存和检索记忆
