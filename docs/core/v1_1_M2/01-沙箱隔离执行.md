# 沙箱隔离执行

Agent 的工具调用（BashTool / FileSystemTools / GrepTool）默认直接跑在宿主机上。启用沙箱后，工具在一个独立容器中执行，文件系统与宿主机隔离；调用结束后工作区状态通过快照持久化，下次调用自动恢复。

不配置 `sandbox(...)` 则完全不启用，工具保持宿主机执行。

---

## 1. 前提条件

| 项 | 要求 |
|----|------|
| Docker | 宿主机已安装 docker CLI，daemon 运行中 |
| 镜像 | 已拉取（如 `docker pull ubuntu:22.04`），镜像内需含 `sh` / `tar` / `base64` / `ls` 等基础命令 |
| 数据库（可选） | 传 `dataSource` 则快照元数据写 MySQL，不传存内存 |

> **应用本身也跑在容器里时（兄弟容器模式）**：应用容器只需装 docker CLI（客户端），并挂载 `/var/run/docker.sock`。沙箱容器由宿主机 dockerd 创建，与应用容器平级，不是嵌套容器。
>
> ```bash
> docker run -d \
>   -v /var/run/docker.sock:/var/run/docker.sock \   # 关键：让容器内能调宿主机 docker
>   my-app
> ```

## 2. 30 秒跑起来（最小示例）

```java
SandboxConfig sandboxConfig = SandboxConfig.builder()
        .backend(DockerBackend.builder().build())   // 默认 ubuntu:22.04
        .isolationScope(IsolationScope.CONVERSATION)
        .snapshotDir("/data/agentx-snapshots")      // 快照目录，本地存储必填
        .build();

ReactAgent agent = ReactAgent.builder()
        .chatModel(chatModel)
        .dataSource(dataSource)          // 可选：元数据写 MySQL
        .tools(tools)                    // BashTool / FileSystemTools 等
        .sandbox(sandboxConfig)          // 传入即启用
        .build();

// 之后正常调用，工具自动在容器内执行
String answer = agent.call("列出当前目录的文件", params);
```

框架自动完成：调用开始时创建/恢复容器 → 工具在容器内执行 → 调用结束时导出快照、销毁容器。

## 3. 配置逐项说明

### 3.1 SandboxConfig（通用配置）

```java
SandboxConfig.builder()
        .backend(...)                    // 必填，见 3.2 / 第 7 节
        .isolationScope(...)             // 隔离级别
        .autoRelease(...)                // 是否调用结束自动销毁
        .strictMode(...)                 // 沙箱失败是否降级
        .workspaceSpec(...)              // workspace 物化规格
        .snapshotDir(...)                // 本地快照目录
        .snapshotStorage(...)            // 自定义快照存储（如 MinIO）
        .snapshotMetadataStore(...)      // 自定义元数据存储
        .build();
```

| 方法 | 默认值 | 说明 |
|------|--------|------|
| `backend(SandboxBackend)` | **必填** | `DockerBackend.builder().build()`（生产）或 `new LocalExecutionBackend(dir)`（调试） |
| `isolationScope(IsolationScope)` | `CONVERSATION` | `CONVERSATION`=同会话共享 workspace；`USER`=同用户跨会话共享（userId 为空时退化为 conversationId） |
| `autoRelease(boolean)` | `true` | `true`=调用结束快照后销毁容器；`false`=**容器常驻**，由调用方显式销毁。详见第 4 节 |
| `strictMode(boolean)` | `false` | `false`=沙箱失败降级宿主执行；`true`=fail-closed，沙箱不可用时工具直接报错。执行不受信任的 LLM 生成命令时建议开启 |
| `workspaceSpec(WorkspaceSpec)` | `empty` | 容器创建后往 workspace 里物化的内容（宿主目录拷贝 / 文件拷贝 / 内联文本） |
| `snapshotDir(Path)` | 条件必填 | 本地快照目录。未注入自定义 `snapshotStorage` 且后端需要快照时必填（构建期校验），生产请指定稳定目录 |
| `snapshotStorage(SnapshotStorage)` | 内置本地实现 | 注入自定义 tar 存储（如 MinIO），注入后无需 `snapshotDir`。多节点部署必须注入共享存储 |
| `snapshotMetadataStore(SnapshotMetadataStore)` | 自动选择 | 不传则按是否有 DataSource 自动选 JDBC / 内存 |

#### workspaceSpec 用法（往沙箱里放初始文件）

```java
WorkspaceSpec spec = WorkspaceSpec.builder()
        .copyDirectory(Path.of("/data/project"), "/workspace/project")  // 宿主目录 → 容器路径
        .copyFile(Path.of("/data/config.yml"), "/workspace/config.yml") // 单个文件
        .inlineText("echo hello", "/workspace/hello.sh")               // 内联文本直接写文件
        .build();

SandboxConfig.builder()
        .backend(DockerBackend.builder().build())
        .workspaceSpec(spec)
        ...
```

### 3.2 DockerBackend（Docker 专属配置）

```java
DockerBackend.builder()
        .image("ubuntu:22.04")           // 容器镜像
        .workspaceRoot("/workspace")     // 容器内工作目录
        .networkDisabled(true)           // 是否断网
        .memoryMb(512)                   // 内存上限
        .cpuCount(1)                     // CPU 上限
        .executionTimeoutMs(120_000)     // 单条命令超时
        .mount("/data/ws", "/workspace") // 宿主机目录挂载，可多次调用
        .build();
```

| 方法 | 默认值 | 说明 |
|------|--------|------|
| `image(String)` | `ubuntu:22.04` | 容器镜像。要求镜像内含 `sh` / `tar` / `base64` / `ls` 等基础命令；需要 python 可直接用 `python:3.12` |
| `workspaceRoot(String)` | `/workspace` | 容器内工作目录（工具执行的 `-w` 目录） |
| `networkDisabled(boolean)` | `true` | `true` 时以 `--network=none` 启动（完全断网）；需要沙箱内访问外网（pip install、curl 等）设为 `false`（bridge 网络） |
| `memoryMb(int)` | `512` | 容器内存限制（MB） |
| `cpuCount(int)` | `1` | 容器 CPU 限制 |
| `executionTimeoutMs(long)` | `120_000` | 单条容器命令（exec / cp / tar）的超时毫秒数 |
| `mount(hostPath, containerPath)` | 无 | 宿主机目录 bind mount 进沙箱容器，**可多次调用挂多个目录**。详见第 5 节 |

## 4. 常驻模式（autoRelease）

### 4.1 两种生命周期对比

| | `autoRelease=true`（默认） | `autoRelease=false`（常驻） |
|--|---------------------------|---------------------------|
| 调用结束 | 导出快照 → 销毁容器 | 什么都不做，容器继续活着 |
| 下次调用 | 从快照恢复（新建容器 + 灌 tar） | 直接复用运行中的容器 |
| 适用场景 | 会话少、强调资源回收 | 高频交互（省掉快照往返的几秒开销）、配合 `mount` 做文件打通 |
| 容器回收 | 自动 | **调用方负责**，用 `destroyByName` 显式销毁 |

### 4.2 用法

```java
SandboxConfig config = SandboxConfig.builder()
        .backend(DockerBackend.builder().build())
        .isolationScope(IsolationScope.USER)   // 常驻通常配 USER 级：同用户跨会话共用一个容器
        .autoRelease(false)                    // 关键：容器常驻
        .snapshotDir("/data/agentx-snapshots") // 仍建议配置：容器异常丢失时兜底恢复
        .build();
```

典型业务流（如「用户开关沙箱」功能）：

```java
// 用户开启沙箱 → 立即拉起常驻容器（可选，也可以等首次调用时自动创建）
DockerBackend backend = DockerBackend.builder()
        .image("python:3.12")
        .build();
String containerName = ContainerNameUtil.toContainerName(String.valueOf(userId));
if (backend.findExisting(containerName) == null) {
    backend.destroyByName(containerName);   // 清理可能存在的 exited 残留（宿主机重启后），避免重名冲突
    backend.createSandbox(WorkspaceSpec.empty(), containerName);
}

// ... Agent 正常调用，容器常驻复用 ...

// 用户关闭沙箱 → 显式销毁
backend.destroyByName(containerName);       // 不管容器在运行还是已停止，都会 docker rm -f
```

> **容器名怎么确定（关键）**：`ContainerNameUtil.toContainerName(scopeKey)`（`sandbox` 包）把 scopeKey 清洗后加上 `agentx-sandbox-` 前缀。scopeKey **不需要从框架取回——它就是你发起调用时传给 `RunnableParams` 的参数**，按你配置的隔离级别取对应字段：
>
> | 配置的 isolationScope | scopeKey 取什么 | 来源 |
> |---|---|---|
> | `IsolationScope.USER` | userId | `RunnableParams.builder().userId("42")` 中的 `"42"` |
> | `IsolationScope.CONVERSATION` | conversationId | `RunnableParams.builder().conversationId("conv_001")` 中的 `"conv_001"` |
>
> 框架内部 `acquire` 创建容器时用的也是这条规则，因此调用方在会话之外（如用户关闭沙箱时）按同样规则算出的名字，必然与框架创建的容器一致。拿不准时 `docker ps | grep agentx-sandbox` 可直接看到实际容器名。

## 5. 宿主机目录挂载（mount）

### 5.1 解决什么问题

默认情况下沙箱容器的文件系统与宿主机割裂：Agent 在沙箱里创建的文件只在容器内，宿主侧看不到（除非走快照）。`mount` 把宿主机目录 bind mount 进容器，**两侧是同一份数据，实时互通**：

- Agent 在沙箱里写的文件 → 立即出现在宿主机目录
- 宿主机放入的文件 → 沙箱内立即可读

### 5.2 用法

```java
DockerBackend backend = DockerBackend.builder()
        .image("python:3.12")
        // 宿主机用户工作区 → 沙箱内同路径；可按用户拼路径，实现每个用户独立工作区
        .mount("/data/workspace/" + userId, "/app/workspace/" + userId)
        // 技能目录也挂进去，沙箱内可读
        .mount("/data/skills", "/app/skills")
        .build();
```

### 5.3 两条约定

1. **hostPath 必须是宿主机真实路径**。沙箱容器由宿主机 dockerd 创建，`-v` 参数由宿主机解析——应用容器内的路径（如 `/app/workspace`）宿主机不认识。应用跑在容器里时，需要把宿主机路径通过配置文件传给应用。
2. **两侧路径建议保持一致**（如上例 `/app/workspace/1` 两侧同名）。这样 `FileSystemTools` 等工具拿到的路径在沙箱内外都能解析，无需做路径映射。

### 5.4 与快照的关系

挂载目录的数据本来就在宿主机上，不依赖快照持久化；快照只管容器内**非挂载区域**的状态（如沙箱里 `apt install` 装的软件）。两者互补：`mount` 管「文件」，快照管「环境」。

## 6. 手动销毁（destroyByName）

`SandboxBackend` 接口方法，按容器名销毁，**不管容器是运行中还是已停止**（Docker 后端直接 `docker rm -f`，能清理宿主机重启后遗留的 exited 容器）：

```java
// 默认实现（SandboxBackend 接口的 default 方法）：只销毁运行中的容器
backend.destroyByName("agentx-sandbox-1");

// DockerBackend 覆盖了此方法：直接 stop + remove，exited 残留也能清掉
dockerBackend.destroyByName("agentx-sandbox-1");
```

与 `destroy(Sandbox)` 的区别：`destroy` 需要 `Sandbox` 实例（调用过程中 acquire 拿到的句柄）；`destroyByName` 只需容器名，适合调用方在**会话之外**主动回收（如用户关闭沙箱开关、定时清理）。

**容器名的确定**：`ContainerNameUtil.toContainerName(scopeKey)`。scopeKey 就是调用方自己传的参数——按隔离级别取 `RunnableParams` 的对应字段，无需从框架查询：

```java
// USER 级隔离：scopeKey = 调用时传的 userId
String name = ContainerNameUtil.toContainerName("42");           // → agentx-sandbox-42
dockerBackend.destroyByName(name);

// CONVERSATION 级隔离：scopeKey = 调用时传的 conversationId
String name = ContainerNameUtil.toContainerName("conv_001");     // → agentx-sandbox-conv_001
dockerBackend.destroyByName(name);

// 典型业务：用户关闭沙箱开关时（USER 级），注销该用户的常驻容器
public void onSandboxDisabled(long userId) {
    String containerName = ContainerNameUtil.toContainerName(String.valueOf(userId));
    DockerBackend.builder().build().destroyByName(containerName);
}
```

## 7. Local 模式（开发调试）

不依赖 Docker，命令直接在宿主机执行，路径限定在指定目录内（无系统级隔离，勿执行不受信任的代码）：

```java
// 一个参数：workspace 目录
SandboxConfig config = SandboxConfig.builder()
        .backend(new LocalExecutionBackend("/data/sandbox-ws"))
        .isolationScope(IsolationScope.CONVERSATION)
        .build();

// 两个参数：workspace 目录 + 命令默认超时毫秒
SandboxConfig config = SandboxConfig.builder()
        .backend(new LocalExecutionBackend("/data/sandbox-ws", 60_000))
        .build();
```

Local 模式文件常驻宿主机磁盘，无需快照（`supportsSnapshot()` 返回 `false`），不要求配置 `snapshotDir`。注意：同一 backend 实例的所有会话共享同一个 workspace 目录，需要会话级隔离时为不同会话构造不同实例。

两种后端对工具完全透明：工具拿到的都是 `ExecutionBackend` 接口，切换后端不改工具代码。

## 8. 容器生命周期（框架内部行为）

了解即可，调用方无需介入。

**acquire（每次调用开始）**，按优先级三选一：

1. `findExisting`：同名容器在跑 → 直接复用（常驻模式、JVM 强杀残留、快照失败保留的容器都走这条路径）
2. 快照恢复：元数据记录存在且 tar 包存在（双重确认）→ 新建容器 + 灌入 tar + 追加物化 workspaceSpec
3. 全新创建：新建容器 + 物化 workspaceSpec

**release（每次调用结束，幂等保证恰好一次）**：

- `autoRelease=true`：导出 workspace 为 tar → 存快照 → 写元数据 → 销毁容器；导出或落盘失败时**不销毁容器**，保留给下次复用，避免 workspace 状态丢失
- `autoRelease=false`：直接返回，什么都不做

## 9. 完整示例（生产形态）

多用户平台，按用户隔离工作区，容器常驻，文件双向打通：

```java
public ReactAgent buildAgent(ChatModel chatModel, DataSource dataSource,
                             String userId, String hostWorkspaceRoot) {

    SandboxConfig sandboxConfig = SandboxConfig.builder()
            .backend(DockerBackend.builder()
                    .image("python:3.12")                     // 沙箱自带 python
                    .networkDisabled(false)                   // 允许访问外网（pip install 等）
                    .memoryMb(1024)
                    .cpuCount(2)
                    // 宿主机用户目录 ↔ 沙箱同路径，双向实时互通
                    .mount(hostWorkspaceRoot + "/" + userId, "/app/workspace/" + userId)
                    .mount("/data/skills", "/app/skills")
                    .build())
            .isolationScope(IsolationScope.USER)              // 同用户跨会话共用沙箱
            .autoRelease(false)                               // 容器常驻
            .strictMode(true)                                 // 沙箱不可用时拒绝执行，不降级宿主机
            .snapshotDir(Path.of("/data/agentx-snapshots"))   // 环境状态兜底
            .build();

    return ReactAgent.builder()
            .chatModel(chatModel)
            .dataSource(dataSource)
            .tools(BashTool.create(),
                    ToolCallbacks.from(FileSystemTools.builder()
                            .allowedDirs("/app/workspace/" + userId)
                            .build()))
            .sandbox(sandboxConfig)
            .build();
}

// 用户关闭沙箱时回收常驻容器
public void shutdownSandbox(long userId) {
    String containerName = ContainerNameUtil.toContainerName(String.valueOf(userId));
    DockerBackend.builder().build().destroyByName(containerName);
}
```

## 10. 常见问题

**Q：沙箱内没有网络，pip install 失败？**
`networkDisabled` 默认 `true`（`--network=none`）。需要外网时显式设 `.networkDisabled(false)`。

**Q：宿主机能看到沙箱里生成的文件吗？**
默认不能（容器文件系统隔离），调用结束只留快照 tar。要实时互通用 `mount` 挂载，见第 5 节。

**Q：应用在容器里，mount 报路径不存在？**
hostPath 写成了应用容器内的路径。沙箱由**宿主机** dockerd 创建，hostPath 必须是宿主机真实路径，通过配置传给应用。

**Q：每次对话都新建容器，慢？**
默认模式每次调用结束销毁、下次从快照恢复，有秒级开销。高频交互改用 `autoRelease(false)` 常驻 + `IsolationScope.USER`，容器跨调用复用。

**Q：宿主机重启后沙箱失效？**
容器变为 exited 状态。常驻模式下下次 `findExisting` 找不到运行中容器会走快照恢复或新建；调用方主动拉起前先 `destroyByName` 清理同名 exited 容器，避免重名冲突。

**Q：多节点部署怎么办？**
三件事：注入共享 `snapshotStorage`（MinIO 等实现 `SnapshotStorage` 三方法）、共享 MySQL 元数据库、调用方对同 scopeKey 的调用加分布式锁（锁粒度与 isolationScope 一致：CONVERSATION 按 conversationId、USER 按 userId）。
