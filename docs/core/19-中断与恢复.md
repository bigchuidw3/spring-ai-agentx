# 19. 中断与恢复（Pause / Resume）

## 1. 概述

AgentX 支持两种暂停机制，均通过 `PauseState` 快照持久化实现断点续执：

| 机制 | 触发方式 | PauseReason | 适用场景 |
|------|----------|-------------|----------|
| **HITL** | PauseAdvisor 自动检测已注册工具 | `HITL_TOOL_REQUEST` | 审批工具、用户信息收集 |
| **Interrupt** | 调用方主动调用 `agent.interrupt()` | `USER_INTERRUPT` | 用户点击"停止"、超时打断 |

**恢复入口统一**：无论哪种暂停，恢复都使用同一个 `agent.resume()` / `agent.resumeStream()` 方法。

---

## 2. 快速开始

### 2.1 配置 PauseStateStore

暂停快照默认存于内存（`InMemoryPauseStateStore`），进程重启后丢失。
生产环境需要配置 `JdbcPauseStateStore` 持久化到数据库：

```java
// 内存模式（默认，测试用）
ReactAgent agent = ReactAgent.builder()
    .chatModel(chatModel)
    .build(); // 自动使用 InMemoryPauseStateStore

// JDBC 模式（生产）
JdbcPauseStateStore stateStore = new JdbcPauseStateStore(dataSource);
// 或通过工厂创建
PauseStateStore stateStore = DataSourceStorageFactory.createPauseStateStore(dataSource);

ReactAgent agent = ReactAgent.builder()
    .chatModel(chatModel)
    .stateStore(stateStore)
    .maxRounds(10)
    .build();
```

### 2.2 自动建表

`JdbcPauseStateStore` 自动创建 `agentx_pause_state` 表：

```sql
CREATE TABLE IF NOT EXISTS agentx_pause_state (
    id                BIGINT       NOT NULL AUTO_INCREMENT  COMMENT '主键',
    conversation_id   VARCHAR(100) NOT NULL                 COMMENT '会话ID',
    reason            VARCHAR(50)  NOT NULL                 COMMENT '暂停原因',
    safe_point        VARCHAR(50)  DEFAULT NULL             COMMENT '中断安全点',
    current_round     INT          NOT NULL                 COMMENT '中断时已完成的轮次',
    interrupted_at    TIMESTAMP    NOT NULL                 COMMENT '中断时间',
    expires_at        TIMESTAMP    DEFAULT NULL             COMMENT '过期时间（TTL 7 天）',
    snapshot_json     LONGTEXT     NOT NULL                 COMMENT '完整 PauseState JSON',
    PRIMARY KEY (id),
    UNIQUE KEY uk_conversation_id (conversation_id),
    INDEX idx_pause_state_expires (expires_at)
) DEFAULT CHARSET=utf8mb4;
```

## 3. 流式 Interrupt + Resume

```java
public void streamingInterruptAndResume() {
    JdbcPauseStateStore stateStore = new JdbcPauseStateStore(dataSource);

    ReactAgent agent = ReactAgent.builder()
            .chatModel(chatModel)
            .stateStore(stateStore)
            .maxRounds(5)
            .build();

    String conversationId = "conv-" + UUID.randomUUID();
    RunnableParams params = RunnableParams.builder()
            .conversationId(conversationId).build();

    String query = "用 500 字介绍 Java 并发编程（让生成时间足够长）";

    // 第一步：启动流式，同时 scheduler 定时触发 interrupt
    ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
    scheduler.schedule(() -> {
        boolean ok = agent.interrupt(conversationId, "用户主动中断");
        System.out.println("[interrupt 返回] " + ok);
    }, 10000, TimeUnit.MILLISECONDS);

    // 阻塞等待结果（收到 Paused 事件）
    PauseState pauseState = TestConfig.collectStreamEvents(agent.streamForResult(query, params));
    scheduler.shutdown();

    // 验证中断原因
    System.out.println("reason = " + pauseState.getReason()); // USER_INTERRUPT
    System.out.println("safePoint = " + pauseState.getSafePoint()); // LLM_STREAMING 或 TOOL_EXECUTION

    // 第二步：恢复
    System.out.println("--- 恢复执行 ---");

    // 方式 A：直接从 DB 恢复（跨进程场景）
    PauseState fromStore = agent.getInterruptedState(conversationId);
    agent.resumeStream(fromStore, Map.of())  // 流式
        .doOnNext(event -> { ... })
        .blockLast();

    // 方式 B：一行 API 恢复（推荐）
    agent.resumeStream(conversationId)
        .doOnNext(event -> { ... })
        .blockLast();

    // 方式 C：恢复时附带用户补充说明（如"换一个方向，重点讲 JMM"）
    agent.resumeStream(conversationId, "换一个方向，重点讲 JMM")
        .doOnNext(event -> { ... })
        .blockLast();
}
```

### 安全点说明

Interrupt 在两个安全点可中断：

| SafePoint | 含义 | pendingToolCalls |
|-----------|------|-----------------|
| `LLM_STREAMING` | LLM 正在生成回复 | 空 |
| `TOOL_EXECUTION` | 工具正在执行 | 含正在执行的工具 |

当 `safePoint=TOOL_EXECUTION` 时，恢复时 `resolveInterruptToolResult` 会重新执行工具获取结果注入回复上下文。

## 4. 流式 HITL + Resume

```java
public void streamingHitlPauseResume() {
    ReactAgent agent = ReactAgent.builder()
            .chatModel(chatModel)
            .askUser(true)                      // 自动注册 AskUserTool + PauseAdvisor
            .maxRounds(10)
            .build();

    String query = "帮我推荐一个旅行目的地";
    System.out.println("Q: " + query);

    // 首次流式调用
    PauseState pauseState = TestConfig.collectStreamEvents(
            agent.streamForResult(query, RunnableParams.empty()));

    // 循环处理暂停（Agent 可能多次提问）
    int pauseRound = 0;
    while (pauseState != null) {
        pauseRound++;
        System.out.println("Agent 暂停（第 " + pauseRound + " 次）");
        System.out.println("reason = " + pauseState.getReason()); // HITL_TOOL_REQUEST

        // 构造用户回答
        Map<String, String> answers = new LinkedHashMap<>();
        for (PendingToolCall ptc : pauseState.getPendingToolCalls()) {
            String answer = switch (pauseRound) {
                case 1 -> "我喜欢海边，预算 5000";
                case 2 -> "5 天行程，两个人";
                default -> "没别的要求了";
            };
            answers.put(ptc.id(), answer);
        }

        // 恢复
        pauseState = TestConfig.collectStreamEvents(
                agent.resumeStream(pauseState, answers));
    }

    System.out.println("Agent 完成（共暂停 " + pauseRound + " 次）");
}
```

### PauseReason 分支处理

```java
while (pauseState != null) {
    if (pauseState.getReason() == PauseReason.USER_INTERRUPT) {
        // 用户主动中断 → 中断的才是 HITL 恢复后被中断的共存场景
        break;
    }
    // HITL → 需要用户回答
    Map<String, String> answers = ...;
    pauseState = TestConfig.collectStreamEvents(agent.resumeStream(pauseState, answers));
}
```

## 5. 非流式 Interrupt + Resume

非流式使用 `callForResult()`，返回 `AgentResult`，通过 `scheduler` 触发 interrupt：

```java
public void callInterruptAndResume() {
    JdbcPauseStateStore stateStore = new JdbcPauseStateStore(dataSource);

    ReactAgent agent = ReactAgent.builder()
            .chatModel(chatModel)
            .stateStore(stateStore)
            .maxRounds(5)
            .build();

    String conversationId = "conv-" + UUID.randomUUID();
    RunnableParams params = RunnableParams.builder()
            .conversationId(conversationId).build();

    // 定时触发 interrupt
    ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
    scheduler.schedule(() -> {
        agent.interrupt(conversationId, "非流式中断");
    }, 5000, TimeUnit.MILLISECONDS);

    AgentResult result = agent.callForResult(
            "调用 slow_task 工具: 测试中断恢复", params);
    scheduler.shutdown();

    if (result instanceof AgentResult.Paused p) {
        PauseState pauseState = p.state();
        System.out.println("reason = " + pauseState.getReason()); // USER_INTERRUPT
        System.out.println("safePoint = " + pauseState.getSafePoint());

        // 恢复（同样走 resume 方法）
        AgentResult resumed = agent.resume(pauseState, Map.of());
        if (resumed instanceof AgentResult.Completed c) {
            System.out.println("A: " + c.answer());
        }
    }
}
```

## 6. 非流式 HITL + Resume

```java
public void callHitlPauseResume() {
    ReactAgent agent = ReactAgent.builder()
            .chatModel(chatModel)
            .tools(AskUserTool.create())
            .advisors(new PauseAdvisor("ask_user"))
            .maxRounds(10)
            .build();

    AgentResult result = agent.callForResult(
            "帮我推荐一份生日礼物", RunnableParams.empty());

    int pauseRound = 0;
    while (result instanceof AgentResult.Paused p) {
        pauseRound++;
        System.out.println("reason = " + p.state().getReason()); // HITL_TOOL_REQUEST

        // 构造回答
        Map<String, String> answers = new LinkedHashMap<>();
        for (PendingToolCall ptc : p.state().getPendingToolCalls()) {
            answers.put(ptc.id(), mockAnswer(pauseRound));
        }

        result = agent.resume(p.state(), answers);
    }

    if (result instanceof AgentResult.Completed c) {
        System.out.println("A: " + c.answer());
    }
}
```

## 7. 恢复方式对比

| API | 参数 | 适用场景 |
|-----|------|----------|
| `agent.resume(pauseState, toolResults)` | PauseState + 工具结果 | 非流式（持有 PauseState） |
| `agent.resumeStream(pauseState, toolResults)` | PauseState + 工具结果 | 流式（持有 PauseState） |
| `agent.resumeStream(conversationId)` | conversationId | 流式（从 stateStore 自动取回） |
| `agent.resumeStream(conversationId, resumeQuery)` | conversationId + 补充消息 | 流式，恢复时追加用户新消息 |

### 会话记录生命周期

`agentx_session` 采用启动即写入策略，而非等到完成后再插入：

| 时机 | 行为 | answer 列 |
|------|------|----------|
| 执行启动 | `INSERT`（仅 question） | NULL |
| 用户中断 | `UPDATE`（部分输出 + timeline） | 已输出的部分文本 |
| 执行完成 | `UPDATE`（最终输出 + timeline） | 完整回答 |

**中断恢复时**：`USER_INTERRUPT` 恢复走新 `sessionId`（新行，question=resumeQuery），`HITL_TOOL_REQUEST` 恢复沿用原 `sessionId`（同一行 UPDATE）。
同 `conversationId` 下多行记录由前端按 `created_at` 排序渲染为多条 Q&A 历史。

`ChatMemory.get()` 自动过滤 answer 为空的未完成记录，不影响后续对话上下文构建。

### 恢复清理

resume 完成后，若结果为 `Completed`，框架自动删除 `agentx_pause_state` 中的快照。
若结果为 `Paused`（再次暂停），新快照通过 `ON DUPLICATE KEY UPDATE` 覆盖旧记录。

## 8. SubAgent 支持状态

SubAgent **当前不支持**中断恢复，`PauseState.children` 字段为 Phase 2 预留。

### 当前限制

- SubAgent 禁止使用 `PauseAdvisor`，不会触发 HITL 暂停
- SubAgent 没有独立的 `PauseStateStore`，快照由主 Agent 统一管理
- SubAgent 作为工具在主 Agent 的 `executeToolCallsAsync` 中同步执行
- 主 Agent 中断时，SubAgent 的执行现场仅体现在 messages 和 pendingToolCalls 中，不会写入独立的 children 节点

### 后续规划（Phase 2）

- `PauseState.children` 递归序列化/反序列化已在 `JdbcPauseStateStore` 中完成预留（`toMap` / `fromMap` 支持递归），接入时只需打通 SubAgent 的暂停链路即可
- SubAgent 可独立恢复，支持嵌套中断场景
